## 下次恢复相同配置

先只核对版本，不启动电机：

```bash
cd /home/khadas/BRUCE/session-save-20261115
python3 launch_validated_stance.py
sha256sum -c SHA256SUMS
sha256sum -c ENTRYPOINT_SHA256SUMS
```

脚本若报告文件改变，先对比并决定采用哪一版本，不自动覆盖新改动。需要恢复旧版本时，先解压到独立目录，确认支架承重、电机关闭后再人工选择文件恢复；不要把整个压缩包直接覆盖系统目录。

下一次真实使能须由现场人员确认支架完全承重、脚稍离地、关节周围清空及急停可立即操作，再更新 sudo 授权并显式运行：

```bash
sudo -v
python3 launch_validated_stance.py --run
```

该入口恢复站姿，不自动踏步。它沿用已验证命令的全部参数；不要在外层使用 `taskset`，监督程序会分配控制核心。程序打印 `/dev/shm/bruce-step-<pid>` 运行目录。双脚放稳、躯干扶正且支架防倒后，由操作者显式创建该目录内的 `operator-ready`，才允许进入落地平衡控制。`operator-stop` 请求受控结束；现场急停独立保留。不要预先创建就位确认文件。

`--seconds 0 --keep-standing` 不安排踏步，也不在正常站立结束后按固定演示时长断动力；通信、姿态、电机故障和监督心跳保护仍生效。落地等待阶段仍有原来的 180 秒超时，不能将它解释为无限期悬空保持。

前后移动不仅要给速度，还必须采用相应的落脚补偿。已验证的命令参考另存于 `motion-sequence-reference.json`，它不是自动执行程序；每次移动后先回站姿并恢复原地补偿，结合足底接触、姿态、电压及现场反馈再继续。

## H-JEPA 究竟需要什么数据

核对本地实际代码：`stable_worldmodel/data/dataset.py` 读取按 episode 排列的 `pixels`、`action`，以及配置选择的 `proprio`；`ep_len` 与 `ep_offset` 定义回合边界。模型按动作预测未来视觉潜表示；连续时序和动作对齐是关键，不是只保存障碍物照片。

H-JEPA 并不强制要求“真实 BRUCE 越障数据”；官方示例同时包含仿真任务和 DROID 实机数据。若论文目标是研究该机器人视觉越障，相关的观测—动作轨迹可以用于训练/微调或独立真实验证，具体取决于实验方案。若只复现官方仿真结果，无须专门采这些实机数据。

当前真实日志和两次相机单帧样例**没有组成同步 episode，不能直接当作 H-JEPA 越障训练集**。相机程序每次运行一段时间后只保存选中的单组原始帧及点云，没有保存完整逐帧 RGB-D 序列。现有 H-JEPA 训练入口也没有接入这些深度/点云；需要选择 RGB 基线或另行设计深度编码与融合接口。

建议的正式记录包含：统一时间轴的 RGB、深度及有效掩码；关节角/速度、IMU、足底接触；在观测之后真正执行的动作及持续时间；电压、电流、错误和急停；相机内外参、拆臂状态、控制版本；障碍几何、是否受支架承重、结果和终止原因。失败轨迹保留并标记，不能当成成功示范。需要以独立外部测量验证运动和障碍尺寸。

仿真当前用固定外部 RGB 相机、36 维真值本体观测和 64 维力矩块动作；实物摄像头视角、拆臂后的动作维数和电机电流并不能直接与其混用。应先统一观测视角、动作语义、关节映射、单位、时间尺度及归一化。电流不直接等于已标定的关节力矩。

真实记录可用于识别仿真中的执行延迟、传感器噪声、关节响应与接触参数，也可作为模型微调/测试集；不会自动变成可任意交互的仿真器。若毕业设计是“仿真训练、实机验证”，通常仍由仿真生成主要探索轨迹，真实记录负责校准和验证，避免把测试轨迹泄露到训练集。
