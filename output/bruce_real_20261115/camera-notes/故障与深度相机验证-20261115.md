# 电机保护停机与奥比中光相机验证

记录日期：2026-11-15。电机故障发生于 2026-11-14 的站姿保持期间。

## 电机失能原因

本次直接触发条件为 `RuntimeError: Leg feedback stale`：腿部反馈时间戳超过 150 毫秒未更新。电机通信日志在此前记录了批量响应超时和约 145 毫秒的循环延迟，随后程序关闭全部 10 个电机的使能。没有正常站立计时到期。

最后一份正常电机读数中，10 个状态码均为 128，输入电压约 15.85–16.00 V。最后正常记录后的通信中断期间没有有效采样，因此不能据此排除瞬时硬件或供电问题，也没有证据把本次停机归为步态参数问题。

同一次启动的单调时钟记录：

| 事件 | 时间（启动后秒） |
|---|---:|
| 最后正常电机快照 | 3500.032 |
| 最后监督记录 | 3500.154 |
| 软件发送全部关闭使能 | 3500.224 |
| 摄像头内置 USB hub 开始被内核发现 | 3509.690 |
| 彩色设备 2bc5:050e 枚举 | 3510.274 |
| 深度设备 2bc5:060e 枚举 | 3510.867 |

用户观察为插相机时或紧接着失能，但内核枚举晚于停机约 10 秒。相机与电机串口位于不同 USB 控制器（相机 EHCI bus 2，电机 XHCI bus 7），不能直接认定为共用同一 hub 的带宽争用。目前已定位保护触发点，底层瞬时中断原因仍未确定。

原始故障归档：`/home/khadas/BRUCE/diagnostics/step-20261114-234029`。
摘要证据：`motor-stop-evidence.json`、`kernel-usb-events.txt`。

## 摄像头读取与处理

官方 Orbbec SDK 1.10.37 ARM64 已安装在本诊断目录的独立 sdk 子目录，未替换机器人控制依赖。SDK 将设备识别为 DaBai，PID 0x060e，固件 RD2434。来源：[官方 SDK 仓库](https://github.com/orbbec/OrbbecSDK)。

已经完成两次真实采集：

- 彩色图：640×480，RGB888。
- 深度图：640×400，16 位深度，单位毫米，0 表示无有效测量。
- 观察到约 27–29 帧/秒。
- 第二组近处场景有效深度约 64.6%，有效点云 165292 点。
- 中心 30×30 像素区域深度中值约 0.390 米，有效率 100%。此数值为相机当前场景的深度测量，未使用外部尺具校验。
- 已用 SDK 标定参数生成 XYZ 点云；`cloud_m.ply` 坐标单位为米。
- RGB 与深度预览未做像素对齐，设备不支持帧同步。本次完成独立采集与处理，未接入机器人运动或避障控制。

第二组输出位于 `capture-02/`：

- `rgb_depth_preview.png`：彩色与深度预览，黑色深度像素为无效测量。
- `depth_mm.png`：毫米单位的无损 16 位深度图。
- `cloud_m.ply`：三维点云。
- `analysis.json`：深度分布、中心距离、帧率等统计。
- `capture.json`：分辨率、深度比例和标定内参。
- `depth.raw`、`color.raw`：原始帧。

`camera_probe.cpp` 是无界面的 C++ 采集程序；`process_capture.py` 只处理已保存的文件，使用现有 numpy/Pillow。
