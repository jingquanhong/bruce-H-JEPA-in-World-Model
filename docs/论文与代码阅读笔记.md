## 2. 论文之间的关系

| 工作 | 主要学习问题 | 编码器与目标 | 与本仓库的关系 |
|---|---|---|---|
| V-JEPA / Revisiting Feature Prediction | 从可见视频内容预测遮挡时空区域的特征 | 在线编码器、EMA 目标编码器、目标停梯度；L1 特征回归 | 提供视频特征预测的基础思路，不等同于动作条件动力学 |
| V-JEPA 2-AC | 根据机器人动作和状态预测未来视觉特征 | 冻结预训练视频编码器，训练动作条件预测器；teacher forcing 加 rollout 损失 | 将视频表征用于控制的参照路径 |
| LeWorldModel（LeWM） | 从像素和动作联合学习可规划的隐动力学 | 编码器和预测器联合训练；MSE 加 SIGReg | 本仓库直接采用的训练基础 |
| H-JEPA | 在多个时间尺度和各自的隐空间内预测、规划 | 上层编码下层状态与动作；各层目标联合优化 | 当前核心实现 |

这条关系是概念和方法的比较，并不意味着本仓库加载 V-JEPA 权重。当前 AntMaze 配置构建的是自身的像素/本体感编码器。

2022 年路线图中的 H-JEPA 是更广泛的分层预测架构设想。当前论文实现其中的分层世界模型与规划部分，不能据此说仓库已经实现完整的 configurator、内在动机、短期记忆与自主智能体。

## 3. 状态与动作如何分层

第 1 层把观测编码为状态，把连续原始动作块嵌入为预测器所需的动作表示。启用本体感时，视觉和 proprio 分支分别编码，再拼接、投影。

对于上层 l，令 s 为 stride，w 为 window_size：

```text
上层状态 Z[t] = E_l(下层状态 z[t*s : t*s+w])
上层动作 U[t] = A_l(下层动作嵌入 u[t*s+w-1 : (t+1)*s+w-1])
```

状态窗口长度是 w，动作窗口长度是 s；二者不是同一个参数。动作从状态窗口最后一个位置开始，以对齐向下一状态的转移。状态窗口必须完整，末端动作窗口可补零并传入 padding mask。

论文报告的实验均使用 w=1，因此高层状态编码是对下采样状态逐点施加 MLP，不是在实验中用长窗口池化。代码额外支持 w>1。

`HJEPA` 是各层 JEPA 的容器，层级不是单个 Transformer 内部的 block。`encode_hierarchical()` 自底向上构造状态和动作流，再将各层裁回自己的训练长度。上层目标会通过这些编码路径影响低层编码器；这不意味着高层损失会经过所有低层预测器。

## 4. 一个具体张量例子：ant_hjepa_l3

该配置中：原始 action_dim=8，第 1 层 frameskip=5，每层 history_size=3、rollout_n=1；第 2、3 层 stride=2、window_size=1。

```text
第 3 层需要 4 个状态
  -> 第 2 层需要 (4-1)*2+1 = 7 个状态
  -> 第 1 层需要 (7-1)*2+1 = 13 个状态
```

当前数据集按 13*5=65 个原始时间位置的 span 读取，以同时容纳动作块。

| 变量 | 形状，不含额外评估列 |
|---|---|
| pixels_level1，编码前 | B × 13 × 3 × 64 × 64 |
| action_level1，动作堆叠后 | B × 13 × 40 |
| proprio_level1 | B × 13 × 27 |
| 第 1 层视觉/本体感分支 | 256 / 128 维 |
| 第 1 层融合状态 | B × 13 × 384 |
| 第 2 层状态，裁剪前 | B × 7 × 384 |
| 第 3 层状态 | B × 4 × 384 |
| 高层宏动作，action_encoder 输出 | 每步 4 维 |
| 高层 action_embed 输出 | 每步 384 维 |

各层最终参与损失的状态与动作流长度都是 4，但每层随机裁剪偏移可以不同。不能先把底层裁为 4 帧再建高层。

一层预测对应 5 个原始环境步，二层对应 10 步，三层对应 20 步。这个训练时间尺度由 frameskip 与 stride 连乘决定，不能用规划 horizon 替代 stride。

默认稀疏底层编码先计算所有层保留状态真正依赖的帧，仅编码这些帧并散射回完整长度。它是计算优化，理解算法时可先按完整序列编码来理解。含随机层或批统计时，严格数值等价仍需具体条件和测试支持，不能只凭架构文档断言。

## 5. 训练目标与梯度

对于 rollout_n=1：

```text
context = emb[:, :history_size]
actions = act_emb[:, :history_size]
pred    = jepa.predict(context, actions)
target  = emb[:, 1:history_size+1]
```

因果 Transformer 一次输出各历史位置的一步预测。常用目标为：

```text
L = sum_l [ MSE(pred_l, target_l) + lambda_l * SIGReg(emb_l) ]
```

`detach_pred_target` 可改变目标梯度；所读 AntMaze H-JEPA 配置没有启用它，因此目标分支也接收预测损失梯度。不要套用早期 V-JEPA 的 EMA/stop-gradient 解释。

SIGReg 将特征投影到随机单位方向，用经验特征函数的 cos/sin 统计匹配标准高斯特征函数 exp(-t²/2)，以避免常量表征坍缩。当前调用输入为 T×B×D，函数首先沿 B 维估计统计，再对时间和投影方向求平均；实现并非直接将 B 与 T 合并后仅计算一个统计量。分布式路径还会规约各 rank 的统计；本次未验证其多卡梯度行为。

rollout_n>1 时，代码用预测状态递归输入，并使用真实后续动作。history_size>1 时加入一步 teacher-forcing 锚点；history_size=1 时避免重复加入首步项。另有 `nsteps` 并行展开分支，应与普通自回归 rollout 区分。

DROID 配置还加入状态/动作正则及逆动力学：从相邻状态预测动作。该项促使表示保留与控制相关的信息。`InverseDynamicsLoss` 只 detach 动作标签，没有 detach 输入状态，因此梯度也会训练状态编码器；现有中文注释中“只训练 IDM”的说法不准确。

## 6. 规划如何落地

```text
eval.py -> planning_eval / droid_eval
        -> build_hierarchical_solver
        -> HierarchicalSolver
        -> 每层 GradientSolver + LevelCostModel
```

当前观测和目标先自底向上编码。最高层优化宏动作，使预测状态接近高层目标；低层再优化自己的动作，使低层预测经过上层编码器后接近上层给出的子目标。

关键代价是 `distance(E_upper(lower_prediction), upper_subgoal)`，不是把不同层的向量直接相减，也不需要将高层状态解码成低层状态。可视化 decoder 与冻结表征 probe 是后处理评估工具，不是常规规划必需模块。

高层宏动作没有直接逆解码成原始动作。低层靠自己的动力学与跨层状态代价寻找可执行动作序列。可选动作一致性代价会将低层动作再编码成高层宏动作比较，所读 AntMaze 配置中该项权重为 0。

GradientSolver 并行维护多个候选动作序列，通过可微 rollout 对动作求梯度，迭代更新并选取低代价候选。高层历史动作队列用于规划先验、初始化和范围约束，不是训练经验回放机制。

规划 horizon 随剩余预算递减；高层 horizon=1 时该层可能跳过，目标代价空间由配置控制。`*_project` 评估可只运行低层动力学，同时将预测投影到高层空间打分。它用于区分“更好的代价空间”和“时间分解”的贡献。

训练历史长度与规划历史长度不能混同：当前层级适配器调用 rollout 未传 history_size，使用其默认值 1。训练中的 history_size=3 不代表规划也使用 3 帧真实历史。

对于 w>1 的扩展，规划存在首状态重复补齐等边界处理，应单独验证对齐。论文报告 w=1，不能把该扩展全部视为论文已实证验证的行为。

## 7. H-JEPA 与 HWM 基线

仓库的 HWM 对照保留多时间尺度、动作编码、预测器及分层规划，但上层状态编码器改为 identity，并关闭上层 SIGReg。因此它有时间层级，却没有 H-JEPA 那样学习到的独立状态空间。

高层更抽象不等于维度一定更低：示例各层状态都是 384 维。抽象意味着保留、丢弃的信息不同。论文用冻结探针检验这一点；时间尺度分离较明显的环境更容易出现选择性抽象。不能断言任何机器人数据上层都会自动丢弃姿态或获得语义概念。

## 8. 已确认问题与验证边界

1. `h_jepa/models/hjepa.py:27` 使用 `isinstance(japas, Sequence)`，形参实际为 `jepas`。已在 `/home/user/miniconda3/envs/hjepa/bin/python` 下直接导入该文件并构造 `HJEPA([torch.nn.Identity()])`，复现 `NameError: name 'japas' is not defined`。该错误已在后续仿真采集任务中修复，并通过模型构造与反向传播检查。
2. 架构文档中用下层 planning horizon 推导时间 span 的段落容易误导；训练模型时间跨度应由 frameskip 和各层 stride 推导。
3. 架构文档的部分预处理描述与当前入口不同：当前训练对已匹配尺寸的 uint8 像素在设备上归一化，不能仅凭文档断言每批都执行图像 resize。
4. BRUCE 的 `verify_hjepa_read.py` 检查的是 HDF5 读取和列契约；其训练键没有 pixels。当前 `encode_hierarchical()` 则直接要求 pixels 流。因此即使该脚本通过，也不足以证明完整 H-JEPA 模型可直接训练 BRUCE 数据。需要确定采用视觉输入，还是改成纯本体感编码路径。
5. 本次没有启动训练、完整规划评估或重现论文指标，也没有修改源码。代码阅读证据与运行成功证据分开记录。
